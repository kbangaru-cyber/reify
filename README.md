# buildseg

Staged point cloud segmentation for building components.

Takes a laser scan of a building and returns its structural and MEP components
(walls, slabs, columns, beams, ducts, pipes) as discrete labeled objects suitable
for BIM authoring tools.

## Status

Early. Scaffolding only. **No model in this repository has been evaluated yet, and
no metrics are reported anywhere in it.** Numbers appear in `results.md` when they
exist, and not before.

| Phase | State |
|---|---|
| A. Evaluation and reproducibility | in progress |
| B. Backbone | not started |
| C. Staged pipeline | not started |
| D. Domain transfer | not started |

## Why staged rather than end to end

The target is offline scan-to-BIM, not robotics. There is no latency budget to
defend, so the pipeline is split into stages that can be trained, measured and
replaced independently. Three reasons this is the better trade here:

1. **It matches where the labels are.** Geometric grouping transfers across
   domains and can train on public data. Naming a component is client-specific
   and label-starved. Splitting them means annotating segments rather than
   annotating whole scenes point by point.
2. **Taxonomies change.** IFC, Uniformat and in-house schedules all differ. With
   a separate classification stage, a new taxonomy retrains a small head instead
   of the whole pipeline.
3. **Segment-level features are strong and nearly free.** Once a segment exists,
   verticality, planarity, thickness, height above floor, area and adjacency are
   cheap to compute and highly discriminative for building elements. In a
   low-label regime a gradient-boosted tree over those features is a serious
   baseline, not a placeholder.

The cost is error propagation: stage 2 can merge segments but can never split
them. Stage 1 is therefore biased toward over-segmentation throughout.

## Pipeline

| Stage | Does | Learned |
|---|---|---|
| 0 | Geometric oversegmentation into superpoints | no |
| 1 | Group superpoints into instances, biased to over-split | yes |
| 2 | Classify each segment into a component type | yes, small |
| 3 | Plane fitting, coplanar merge, export to structured objects | no, rules |

Continuous surfaces (walls, floors, ceilings, slabs) and discrete objects
(columns, beams, ducts, doors, windows) are handled differently: the former are
recovered as surfaces in stages 0 to 1 and only become discrete objects in stage
3, since a wall has no natural geometric boundary where it meets another wall.


## Data

Pretraining uses ScanNet v2. ScanNet is distributed under its own terms of use:
request access through the official process at
<http://www.scan-net.org/> and use the download script the maintainers provide.
This repository ships no scenes, no downloader that bypasses that process, and no
checkpoints.

Planned for domain transfer, none integrated yet:

- S3DIS, which labels beams and columns in addition to walls and ceilings
- Rohbau3D, real LiDAR of buildings in shell construction and renovation
- SPC, synthetic scans derived from BIM models with component-level labels

ScanNet's 20 classes are furniture-centric and captured with handheld RGB-D.
Terrestrial laser scans of residential and industrial buildings differ in noise,
density and class distribution, so ScanNet is treated as pretraining only.

## Non-goals

- Real-time or on-robot inference. This runs offline in batch.
- Replacing the modeler. The intended shape is assistive: propose components,
  let a person correct them, and make correction cheap.
